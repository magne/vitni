Keyboard & accessibility

The app is fully operable by keyboard and targets WCAG 2.2 AA. This is the contract the build follows: the shortcut map (also the ? overlay), the focus model, and the ARIA roles each pattern uses. Press ? on any screen to open this as an overlay.

Accessibility is built into the component layer (PR1) and the shell (PR2), then checked as a per-screen acceptance gate — keyboard-only walkthrough, visible focus, correct roles/labels, SSR aria assertions, an axe-core pass, and contrast for both themes.
Global shortcuts are user-rebindable, in Preferences → Keyboard shortcuts (preferences.html) — a chord is typed as the canonical mod+shift+alt+key string (e.g. mod+shift+q); mod resolves to ⌘ on macOS and Ctrl elsewhere. The Go to, Within a screen, and Editing a record chords below are fixed — they are widget-owned (roving focus / the g-prefix state machine), not part of the rebindable map (ADR 0030).

Focus & navigation model

  • Tab moves between regions; arrows move within. Composite widgets use a roving tabindex so the list, tab strip, and pedigree are each a single tab stop, then arrows move inside.
  • Focus is always visible — a strong :focus-visible ring on every interactive element; never removed without replacement.
  • Dialogs trap focus. A modal and a record side panel each bracket their content with a pair of offscreen guards, so Tab/⇧Tab cycle between their own controls and never reach the shell behind them; focus moves in when the dialog opens and back to the control that opened it when it closes. The palette and this help overlay hold focus on their single control. Esc closes — and over a pending close it is the confirm's Cancel, so nothing is discarded.
  • Skip link ("Skip to content") is the first tab stop, jumping past the rail to <main>.
  • Reading order matches visual order; 200% zoom / reflow supported.
