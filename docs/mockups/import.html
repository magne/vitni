Import

One Tool::Import screen, two independent wizards. A mode switch (issue #191) picks Bulk file import — a local file through a bulk-import plugin, the GUI counterpart of vitni import <plugin> <file> (--new NAME PATH | --into NAME) — or Assisted online import, the Digitalarkivet wizard below. Bulk import's target radio reuses the Preferences "Register workspace…" fields for a brand-new workspace, and confirms first (a Modal, no --yes equivalent) before writing into an existing workspace that already holds persons. When that workspace already holds earlier imports in the same format, the import starts at once and the confirm comes once the file is read: it asks which tree the file belongs to — a later export of one of them, or a different tree. Vitni proposes the tree whose earlier imports hold the file's people and families under the same header fingerprint, starts the select on it and says why. A later Vitni export of one workspace always shares that fingerprint, because the exporters write the workspace's id: GEDCOM as HEAD.FILE (ADR 0043), Gramps XML as the researcher's name (ADR 0045). With no clear match nothing is chosen and the import waits for the answer (ADR 0037 §3; the CLI's --dataset / --new-dataset, or its prompt, which --yes accepts). Cancel there writes nothing. Every import is recorded as an import run. The plugin reads the whole file first, naming its own steps; Vitni then writes the records, and a cancel before then writes nothing. A cancel while writing leaves the run interrupted: Resume, on its row in the Dashboard's Recent activity or in the Source stage's Earlier imports, re-runs its plugin over the same file into the same tree at once, so its plan resolves what was written as unchanged and writes the rest (ADR 0040 §5). Only a tree's newest import can be resumed, and not one whose importer rejected the file, which a re-run would repeat.

After a re-import · what it changed, and why

A re-import replaces a single value — a date, a title, a place's coordinates — only when the file says it was exported no earlier than when the value it replaces was recorded, whoever recorded it (ADR 0029 §1). An older file, or one with no export date the importer can read, leaves the value as it is. Nothing asks: the replacement is an ordinary supersession, kept in the record's History like any correction and undone the same way. The run's row opens with What it changed to the changes it made to this record, and the supersession says why, worded from the run's file and export date in the UI's language (ADR 0049). A re-import that replaces a person's sex does not yet name its run, so that one change shows as a plain software-agent entry.

Assisted online import — Digitalarkivet

Fetch, review, and import one record at a time. This wizard renders a typed present payload sent by an assisted-import plugin — it is not the ADR 0022 plugin-UI vocabulary. The plugin fetches pages over the sandboxed net capability, stores the scan through media-store, and proposes fields; you confirm or edit each record before anything is written. Every imported claim is a low-confidence Software-agent assertion with an ExternalId back to the source URL, so a re-run imports no duplicates. Besides the person, a record brings its birth (dated from the age when the census gives one), its part in the census of its residence — the farm, inside the census municipality — with its place in the household's family, or its part in a church-book event by its role. When a record's person, place, source or repository may already be in your tree, the host itself asks before anything of the record is written (the Match stage below); a record with no possible match never meets that stage. When the record would add to a record already in your tree — a reused source's missing repository, say — the host shows that too, before it writes (Ready to import, below; ADR 0046); a record that adds to nothing stored meets neither stage.

One pair at a time, best candidate first. Same on a person imports the record as its own persona and merges it into the person in your tree, so the record's evidence stays a unit you can unlink later; on a place, source or repository it reuses the one in your tree, adds what the record has and it lacks — a source's missing author, a place's unset type, another name or restriction — without replacing anything it already has, and the next run resolves the record onto it. Not the same records that the two differ and shows the next candidate, if any. Decide later imports the record as new and leaves the pair for the review queue. Skip record imports nothing of this record; Cancel import ends the session. Each decision is yours, recorded with its reason, confidence and the assessment shown — the imported claims stay the importer's.
