Plugins are sandboxed WebAssembly with deny-by-default access. A plugin can only touch what it has declared and you have granted — there is no ambient filesystem, network, or database. Each capability (log, query, commands, …) is a separate gate, enforced by the host at the WASM boundary with fuel and memory limits. Import/export run as a software agent, so everything they write is still in the audit trail.

Capability grants

The effective grant is what a plugin declared intersected with what you approved — still deny-by-default. A sanctioned or user-trusted plugin defaults to all declared; an untrusted plugin is granted nothing until you approve each capability.

What a capability means

logEmit diagnostic log lines to the host. No data access.
queryRead projections (people, sources…) — read-only.
commandsSubmit commands that append events to the log.
filesScoped WASI preopen of a named directory (e.g. workspace media/) — no ambient filesystem. Ambient grant, not a WIT interface (ADR 0011: interfaces are log · query · commands).
netOutbound network — denied for all bundled plugins.

Trusted publishers

Pin a publisher's ed25519 public key to trust their signed plugins as user-trusted — for this machine only (ADR 0014 §3). Sanctioned first-party plugins are trusted by the embedded project key and need no pin.
