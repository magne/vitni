Record tabs

The strip shows only on entity categories, beside the Explorer — the Dashboard is full-width and has none. A tab is a record you have open; drag one onto the detail pane (or press ⌘⇧1…9) to dock it side-by-side.

A draft tab names itself by what has been typed into it — “Anna Berg” above — and that is the same label the record is stored with, so a tab never renames itself on Save. A draft with nothing that names it yet is named by the create pane it opens — “New person”, the pane’s own heading, so a tab and the form under it can never disagree — and from the second such draft of a category onwards it carries an ordinal (“New person (2)”), so two new records of one kind never share a name or an accessible name. ⌘N always starts another draft; several can be open at once.

The ● marker means the tab holds unsaved work — either a draft that has been typed into (nothing stored yet, as with “Anna Berg”) or unsaved edits to an already-saved record (“Mary Doe”). Both make ⌘W and ⌘Q ask before discarding — see Record editing. A create form nobody has typed into (“New person (2)”) holds nothing to discard, so it carries no marker and closes without a dialog; typing anything into it raises the marker, and backspacing over it again clears it. Every tab holding unsaved work carries the marker, not just the active one: an in-progress edit is parked per record in shell state, so it outlives its editor and stays visible from the strip while another record is on screen. The marker is a glyph plus an “unsaved changes” accessible name, not colour alone (WCAG 1.4.1); the docked tab's accent underline is the same convention.
The ‹ › buttons at the head of the strip are back/forward through the navigation history — not a scroll control (the tabs scroll themselves). They step through the places you have had a record in focus: opening a record, activating another tab, and opening a draft. A bare category list with nothing focused is never a stop, so back never replays an empty list. Each button is disabled at its end of the history — above, forward is, because the strip is at the newest stop.

A draft's stop lasts exactly as long as its tab. Cancel (or close) the draft and its stops go with it, so back steps to whatever was in focus before it — never onto a tab that is no longer there. Save it and its stops become the record it stored, so back and forward land on that record's tab; the draft and the record it became are one stop, not two.

The same two steps have keys, so they work with the strip off screen: ⌘← and ⌘→. Only with the modifier held — a bare ← → still moves across a record's detail tabs (see Shortcuts).

Docking a record beside the active one

Dragging a tab onto the detail pane (or ⌘⇧1…9) opens it docked, side by side with the active record. The docked pane is a full second editor, not a read-only preview: its own record heading (an <h2>, subordinate to the active pane's single <h1>) and its own related-item tab strip, independently operable — clicking a tab in either pane changes only that pane, exactly like two separate screens. Each pane's tab/panel ids are scoped per pane (docked- prefixed for the docked side) so the two strips never collide. Below lg the split stacks into two rows rather than being dropped or clipping the second pane off-screen.

Quitting with unsaved work

⌘Q with anything unsaved raises one dialog for the whole set: it lists every record at stake by its tab name — a stored record by its own label, a draft by whatever has been typed into it, falling back to “New <entity>” with an ordinal from the second empty draft of a category — so the choice is made over the actual list, not over “one or more”, and two unnamed drafts are never one indistinguishable pair of entries. A create form nobody has typed into is not at stake and is not listed; with nothing else unsaved, ⌘Q quits without a dialog even with such a draft open. Save all walks the records it can save in strip order, activating each and running that record's own Save, and quits once the last one lands — but only when that was every record listed. A record it cannot save yet is marked in the list and simply left open, with the app still running; it is never saved, and never lost. Discard all quits and loses the work; Cancel backs out with every tab and every edit intact. The window's own ✕, a session logout and wmctrl -c raise the same dialog, and Cancel leaves the app running just as it does for ⌘Q — a close with nothing unsaved still closes immediately. Per-tab closing is Record editing §5a.

orderOne record saves at a time: only the active tab's editor is mounted, so the run activates each in turn. A record whose save fails stops the run — the remaining tabs keep their edits and the app does not quit.
left openA listed record that cannot be saved yet — an invalid edit, or a draft still missing a required field — is marked in the list and left open when Save all runs. The run saves the rest and the app keeps running, so the quit waits until that work is dealt with.
blockedSave all is disabled only when no listed record can be saved; then the body names the first one standing in the way. One unsavable record never speaks for the ones beside it. Discard all and Cancel stay available either way.
target goneA record still waiting its turn in the run — queued, or the one currently being saved — can disappear before it saves: its tab closes or its create draft is cancelled, or its parked edit stops passing the Save gate. Either way it is dropped from the run, which then moves on to whatever is left rather than waiting on a report that will never come. If that leaves no unsaved work at all — the disappearing tab took its own work with it — Save all still quits normally. If unsaved work remains, the quit does not fire and a notice says so instead of the app silently staying open with no explanation.
window ✕A close the app did not start — the titlebar ✕, a session logout, wmctrl -c — is held back and raises this same dialog, so the one close path reached with the mouse cannot discard an edit either. Cancel leaves the app running with every tab and edit intact; Discard all quits. With nothing unsaved the close is not held back at all and the window closes immediately.

New from anywhere — the ⌘N picker

⌘N is context-aware: on an entity category (People, Places, Tags, …) it opens a new draft there, in place, exactly as before. Everywhere else — the Dashboard, a tool (Import, Pedigree, Preferences, …), or Help — there is no category to create in, so it raises this picker instead of doing nothing. Picking a category reveals it and opens a draft there, the same as the tabstrip's own + menu; Esc or a click on the scrim dismisses it without creating anything.

Feedback — the toast layer

Every save/undo/error confirmation goes through one shell-owned notice, rendered by one positioned layer — .toast-layer — pinned to the bottom-centre of the work area, out of grid flow so a notice never shifts the layout it reports on. Only one toast is ever up at a time; a second notification replaces it rather than stacking. A confirmation (role="status", aria-live="polite") auto-dismisses after 6 seconds; an error (role="alert", aria-live="assertive") stays up until Dismiss is clicked. .toast is the surface component (it also appears in flow elsewhere, e.g. the design system specimens); .toast-layer is the one place the shell actually positions it.
