Record tabs

The strip shows only on entity categories, beside the Explorer — the Dashboard is full-width and has none. A tab is a record you have open; drag one onto the detail pane (or press ⌘⇧1…9) to dock it side-by-side.

The ● marker means the tab holds unsaved work — either an unsaved draft (nothing stored yet, as with “New person”) or unsaved edits to an already-saved record (“Mary Doe”). Both make ⌘W and ⌘Q ask before discarding — see Record editing. Every tab holding unsaved work carries the marker, not just the active one: an in-progress edit is parked per record in shell state, so it outlives its editor and stays visible from the strip while another record is on screen. The marker is a glyph plus an “unsaved changes” accessible name, not colour alone (WCAG 1.4.1); the docked tab's accent underline is the same convention.

Docking a record beside the active one

Dragging a tab onto the detail pane (or ⌘⇧1…9) opens it docked, side by side with the active record. The docked pane is a full second editor, not a read-only preview: its own record heading (an <h2>, subordinate to the active pane's single <h1>) and its own related-item tab strip, independently operable — clicking a tab in either pane changes only that pane, exactly like two separate screens. Each pane's tab/panel ids are scoped per pane (docked- prefixed for the docked side) so the two strips never collide. Below lg the split stacks into two rows rather than being dropped or clipping the second pane off-screen.

The docked pane's own strip is independent — it is on Names here while the active pane (left) is on Overview, and clicking either changes only that pane.

Each open record remembers its own last-active tab while its tab stays open — reopening a record (or bringing it back from a remount, e.g. switching away and back) restores the tab it was left on rather than flashing back to Overview. The memory is forgotten when the record's tab closes, and carried along if the record is renamed; a create draft has no tab strip, so it never has one to remember. ⌘Z stays scoped to the active record even with a split open — the docked pane never answers for an undo it wasn't addressed.

Quitting with unsaved work

⌘Q with anything unsaved raises one dialog for the whole set: it lists every record at stake by its tab name — a draft as “New <entity>”, a stored record by its own label — so the choice is made over the actual list, not over “one or more”. Save all walks the records it can save in strip order, activating each and running that record's own Save, and quits once the last one lands — but only when that was every record listed. A record it cannot save yet is marked in the list and simply left open, with the app still running; it is never saved, and never lost. Discard all quits and loses the work; Cancel backs out with every tab and every edit intact. Per-tab closing is Record editing §5a.

orderOne record saves at a time: only the active tab's editor is mounted, so the run activates each in turn. A record whose save fails stops the run — the remaining tabs keep their edits and the app does not quit.
left openA listed record that cannot be saved yet — an invalid edit, or a ⌘N draft nothing has been typed into — is marked in the list and left open when Save all runs. The run saves the rest and the app keeps running, so the quit waits until that work is dealt with.
blockedSave all is disabled only when no listed record can be saved; then the body names the first one standing in the way. One unsavable record never speaks for the ones beside it. Discard all and Cancel stay available either way.

Feedback — the toast layer

Every save/undo/error confirmation goes through one shell-owned notice, rendered by one positioned layer — .toast-layer — pinned to the bottom-centre of the work area, out of grid flow so a notice never shifts the layout it reports on. Only one toast is ever up at a time; a second notification replaces it rather than stacking. A confirmation (role="status", aria-live="polite") auto-dismisses after 6 seconds; an error (role="alert", aria-live="assertive") stays up until Dismiss is clicked. .toast is the surface component (it also appears in flow elsewhere, e.g. the design system specimens); .toast-layer is the one place the shell actually positions it.
