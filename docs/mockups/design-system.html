Buttons

A disabled button (e.g. Save while a required field is empty) dims and shows a not-allowed cursor — the state is never left to look active.

⇄ Compare appears on record heads with a duplicate/merge-compare story — Person, Family, Event, Place, Source — and is deliberately omitted on the other aggregates (Citation, Repository, Media, Note, Tag, DnaTest, DnaMatch).

Per-row action buttons (table rows, cards) carry a contextual aria-label — e.g. "Edit participant: John Smith (groom)" — because a title attribute never reaches the accessible name. person.html and event.html carry the reference exemplars.

A ghost button is borderless at rest. Hovering a table row or .row reveals a --line-2 boundary on every ghost action inside it; the one under the pointer takes a --muted boundary and a --panel-3 fill, which clears the 3:1 non-text floor against the row's own hover tint (--panel-2) instead of vanishing into it.

Row primitive — FactRow

Every record row is one .fact-row: a fixed-width .field-label, then the value or the control beside it on the same line. Read and edit mode use the same row, so toggling a record between them moves no text. It ships as the FactRow component in vitni-ui-dioxus/src/components/; the label is a <label for> when it names a control and a bare <span> when it names read text.

A value the record does not carry reads as an em dash, never as an empty row. 96px is the default for a card of ordinary fact rows, and 110px the floor for a whole-record card, which always carries a Restrictions row (Record editing §3). A card overrides both where its own longest label needs more room — 140px on Person, Citation, DNA match and the Source Reliability card, 130px on Tag; and less where it can, 64px on the Family marriage rows, 80px on the Repository contact card. The width is a call-site decision, not a token: the rows of one card line up with each other, not across cards — so it is sized against the longest label that card renders, in every shipped locale, never against this specimen.

Field states — modified & no-reflow

A field whose draft differs from its original gets an inline reset icon at its right edge (left of any native chrome — a select's dropdown arrow), shown only while changed. A record can have more tabs than fit, so the strip scrolls horizontally. Its scrollbar is suppressed and the right-edge fade is the overflow signal; wheel, trackpad and keyboard focus do the scrolling. That is a hit-target decision, not a cosmetic one — the row is one 36px line, and a scrollbar's hit rectangle would claim its lower half, so a click on the label's own centre would scroll the strip instead of switching the tab. Dialog layer — scrim, focus trap, motion

A .modal ships on the shared .overlay layer, which carries the backdrop wash. Over it a .modal-scrim button catches a click outside the dialog and dismisses it — the same click-away the .sidepanel-scrim gives the side panel; it is a <button> so it has an accessible name. A pair of offscreen .focus-guard tab stops brackets the dialog's content: tabbing onto one sends focus to the opposite end, so Tab/⇧Tab cycle inside the dialog and never reach the inert shell behind it. Focus moves into the dialog on open and back to the control that opened it on close. What "inert shell" means differs by layer: a .modal sits on .overlay, a sibling of .app, so .app itself takes inert; a .sidepanel lives inside .app, so each region behind it — the rail, Explorer, top bar, tabstrip, status bar, notice layer, skip link, and the record container the panel is a sibling of — takes inert on its own root instead. Both overlays slide in; the prefers-reduced-motion block drops the motion.

Record picker & nested draft

A record link is a find-or-create picker wherever it appears — a create form, the provenance block, an attach side panel — over reused .row markup, a trailing .picker-new row, and a collapsed .picker-value once a record is picked. The result list floats: .picker-results (components.css) is an absolute dropdown hanging off the .picker-anchor that wraps the input — which is what the specimen below draws, with no renderer to measure anything. In the app the renderer adds .picker-results-viewport, which re-places the same list position: fixed at the anchor's measured on-screen box, so it floats free of whatever scroll container the field sits in rather than being clipped by it. “+ New …” opens a .draft-card nested in its container; surfaces alternate as cards nest.

Responsive & layout

The UI is responsive from the foundation. Breakpoints (in tokens.css): --bp-sm 640px, --bp-md 960px, --bp-lg 1280px.

Fluid type
Each --fs-* is a clamp(min, vw, max): the sizes above are the floor (never shrink below them) and grow a step on wide screens. Text reflows cleanly at 200% zoom (WCAG 2.2 §1.4.10).
Adaptive layout
  • < lg (exclusive — 1280px, the app's own default window, keeps the two-column split): a docked pane (.split-2) stacks into two rows, each still its own full, operable editor, rather than losing or clipping the second pane.
  • < md: single column — the rail becomes a horizontal nav strip, and the shell-level Explorer list stacks above the editor area (.master-detail itself carries no list column any more; that moved to the shell).
  • Side panel, modal, and palette widths are min(px, 92vw) so they never overflow a narrow viewport; tables scroll horizontally inside their wrapper.
  • Interactive controls keep a ≥24×24px hit area (WCAG 2.2 §2.5.8).

Accessibility & keyboard

A11y is part of the component contract, not a later pass. Full shortcut map, focus model, and per-pattern ARIA roles live in Keyboard & accessibility (press ? on any screen). Targets WCAG 2.2 AA.
