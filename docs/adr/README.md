# Architecture decision records

One file per decision, numbered in the order they were accepted. **An accepted ADR is never edited**: a
later ADR that changes it says so, naming the section it supersedes, and the earlier one stands
everywhere else. 0016 is reserved and not yet written, for the server backend and web frontend
([`roadmap.md`](../roadmap.md) Phase 13). 0031 was reserved for the place model and accepted after 0052.

Find the ADRs that bear on a change by its keywords below, then read those, and the ADRs their
**Relations** name. A relation is one of three, each read from the later ADR's own text:

- **Supersedes** / **Superseded by** — replaces the decision, or only the section named;
  the rest of the earlier ADR stands.
- **Amends** / **Amended by** — changes part of the decision (narrows it, replaces a type or a shape,
  drops a rule) without replacing it.
- **Extends** / **Extended by** — adds to the decision and keeps it, including closing a deferral it named.

An ADR that only builds on, applies or cites another has no relation to it. A section after the number
(`0009 §1`) is the part of the earlier ADR that changed; a note in parentheses says what changed.

To add one, take the next number, copy an existing ADR's header (`Status`, `Date`), and add its row to
this table in the same change, with its relations, and each relation's inverse in the earlier ADR's row.
`cargo xtask adr-index` (part of `cargo xtask check`) fails while an ADR has no row, or two, or a relation
has no inverse.
